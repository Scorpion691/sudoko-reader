1Abstract and system overview

Reading a Sudoku from handwriting fails in a very specific way: one misread digit usually makes the whole puzzle unsolvable, even though the network is right about 98% of the time. We exploit the structure of the problem. A neural network reads the grid and gives a probability for every digit; a constraint solver tells us whether the reading is consistent; and a search procedure looks for the least unlikely set of corrections (cost = how much less likely the new digit is) that makes the puzzle solvable. The three components cooperate in one loop, and when nothing works the system reports that the puzzle is unreadable and lists the least confident cells.

What was built

  • Data pipeline: reproducible MNIST preprocessing, a seeded Sudoku and handwritten-mosaic generator, and a documented rule for injecting hard digits.
  • Neural network: a 784-128-64-9 MLP written in NumPy with temperature-scaled probabilities, compared with logistic regression.
  • CSP: backtracking, forward checking and AC-3 as three separately switchable parts with counters (assignments, backtracks, revisions).
  • Search: UCS, Greedy best-first and A* with an admissible heuristic over correction sets, with counters (expanded, generated, CSP calls).
  • Evaluation and tooling: 19 automated tests, three experiments with 5 seeds, an interactive dashboard and a desktop launcher.

2Data

2.1 Real data: MNIST

The classifier is trained on the MNIST database of handwritten digits (60,000 training and 10,000 test images, 28×28 pixels, training and test writers are different people). The four gzip files are fetched by data/make_data.py and a fixed seed makes the preprocessing reproducible. As the project asks, the 60,000 training images are split 50,000 / 10,000 (train / validation) with a seeded permutation, scaled to 0–1, and the digit 0 is dropped because Sudoku only uses 1–9. The official test set is never used for training or model selection, and the mosaics below are built from test images only, so the network has never seen the digits it must read.

2.2 Generated data: puzzles and handwritten mosaics

There is no real handwritten-Sudoku dataset in the project, so the puzzles are generated with a seeded random generator (data/generator.py). A full grid is built by randomised backtracking (MRV cell order, shuffled digits). Cells are then removed in random order, keeping a cell removed only if the CSP still finds exactly one solution, until the wanted number of givens (25, 30 or 35) is reached. Each given is replaced by a random real MNIST test image of that digit and each empty cell by dark Gaussian noise (σ = 0.02), giving a 252×252 mosaic. Empty cells are detected by a brightness rule (brightest pixel < 0.5), not by the network.

2.3 Injecting hard digits

A well-trained network is almost always right, so on its own there would be nothing to correct. For a level of k misreads we replace k given cells by a hard digit: a test image of the same true digit that the network misreads, and for which the true digit is ranked second or third. For k ≥ 1 the draw is repeated (at most 30 times) until the first reading is unsolvable, so that every instance really is broken.

3Neural network

The network classifies one 28×28 cell image into a digit 1–9 and returns the full probability vector, because the search needs the probabilities, not only the arg-max. To keep the whole project light on the CPU the network is implemented in NumPy (nn/mlp.py, about 120 lines) and trains in roughly 20 seconds without a GPU.

Architecture and training

  • 784 → 128 → 64 → 9, ReLU, softmax, He initialisation
  • Cross-entropy loss, Adam (β1=0.9, β2=0.999), learning rate 10−3
  • Mini-batches of 128, 10 epochs, seed 0
  • Baseline: multinomial logistic regression (784 → 9) with the same trainer

Temperature scaling

Probabilities are divided by a temperature T before the softmax. T is picked on the validation set by minimising the negative log-likelihood over a grid from 0.5 to 4.0, giving T = {{temp}}. This does not change the arg-max, so accuracy stays the same while the probabilities become better calibrated.

Why calibration matters here

The probability vector becomes the cost of a correction. For a cell read as digit a and changed to b:

cost(a → b) = log( pa / pb ) ≥ 0

It is never negative because a is the arg-max, and it is small when the network was nearly as sure about b. A poorly calibrated network would make the cheapest correction the wrong one.

4Constraint satisfaction

Formulation

  • Variables: the 81 cells.
  • Domains: digits 1–9; a given cell has a single-value domain.
  • Constraints: 27 all-different constraints (9 rows, 9 columns, 9 boxes), modelled as binary “not equal” constraints between each cell and its 20 peers.
  • Representation: a domain is an integer bit-mask, so removing a value is one AND and the domain size is a population count.

Switchable parts

PartWhat it does
Backtrackingdepth-first assignment, undo on failure
Forward checkingafter each assignment remove the digit from the peers' domains; fail on an empty domain
AC-3run once before the search; detects conflicts (two equal givens empty a domain) and shrinks domains

The three parts are separate switches of csp.sudoku.solve(grid, fc, ac3_on, mrv, limit, max_assignments), so any combination can be measured. Variable ordering is static by default in the experiments (so the effect of the inference is not hidden by a strong heuristic) and MRV is used inside the integrated system. Asking for limit = 2 solutions gives a uniqueness test, which the generator and the optional “exactly one solution” goal use.

Counters

Every run returns assignments (values tried), backtracks (variables whose values were all exhausted), AC-3 revisions (arc revisions) and pruned values. A cap on assignments protects the experiments from the very hard cases of plain backtracking.

Impossible inputs

Two equal givens in a unit, or a cell with no legal digit, give the explicit message “no solution: …” (AC-3 empties a domain, or the search is exhausted). Both cases are covered by unit tests.

5Search over corrections

Problem definition

  • State: a set of corrections {(cell, new digit)} applied to the first reading; each cell is corrected at most once.
  • Actions: correct one more uncertain cell to one of its top alternatives.
  • Step cost: log(pread/pnew) ≥ 0.
  • Goal: the corrected puzzle is solvable (optionally: has exactly one solution).
  • Limit: at most 3 corrections by default (4 in the experiments).

Keeping the branching small

Correcting any of 81 cells to any of 8 digits would be hopeless. Only the 15 cells with the smallest margin between the best and second-best probability are candidates, each with its 2 most likely alternatives: at most 30 actions per state, and states are deduplicated because order does not matter. The goal test calls the CSP; a state with a duplicate pair that no candidate can fix is pruned without calling it.

The three algorithms

AlgorithmPriorityOptimal?Role
UCSg (cost so far)yesfinds the most likely correction set
Greedy best-firsthnofew expansions, may call the CSP more often
A*g + hyes (admissible h)UCS-quality answer with fewer nodes

Heuristic and why it is admissible

Every duplicate-digit conflict (two equal digits in one unit) must be resolved, so at least one of its two cells has to change. Changing a cell c costs at least its cheapest alternative m(c) and a cell that is not a candidate cannot change at all. Hence:

h(state) = max over conflicts (a, b) of min( m(a), m(b) ) (h = ∞ if no candidate can fix a conflict)

Any solution must pay at least this much for the single hardest conflict, so h never overestimates the remaining cost. It is evaluated on the corrected grid of each state, and states reached by a cheaper path are re-opened, so A* returns the same optimal cost as UCS. The test suite checks UCS and A* against a brute-force enumeration of all correction sets on a small pool.

Counters and guard rails

Each run reports nodes expanded and generated, the number of CSP calls and their total CSP effort. A cap of 4,000 expanded nodes protects the experiments; a run that reaches it counts as a failure. If the open list empties, the answer is unreadable.

Design choice: the goal is “solvable”, as in the project brief. The cheapest solvable puzzle is sometimes a different valid puzzle, which is the main source of failures analysed in Section 10; the optional “unique” goal addresses it.

6Integration

The integrated system (integration/pipeline.py) connects the three parts exactly as the brief describes:

  1. Read. Empty cells are found by the brightness rule; the network gives a probability vector for every other cell and the first reading is its arg-max.
  2. Check. The CSP runs on the first reading. AC-3 finds duplicate givens immediately; if the puzzle is solvable the system returns its solution, with no correction and no search.
  3. Correct. Otherwise the search proposes correction sets in order of cost (UCS, Greedy or A*).
  4. Test. Each proposal is passed to the CSP. The first solvable one wins (or the first with a unique solution, in the extension). If the CSP fails, the proposal is discarded and the search continues.
  5. Report. The result contains the corrected puzzle, its solution and a correction log: cell, read digit, new digit, cost.
read, p = network(image)                      # arg-max reading + probabilities
if csp.solve(read).solved:  return solution   # nothing to correct
for corrections in search(read, p, algo):     # cheapest first
    if csp.solve(apply(read, corrections)).solved:
        return solution, corrections          # first solvable puzzle wins
return "unreadable", 5 least confident cells

When there is no solution

If no puzzle is reachable within the correction limit, the system says unreadable and lists the least confident cells (cell, digit read, confidence) so that a person knows where to look. A reading that is unsolvable with correction switched off is reported as no solution.

Code layout and tests

The code is split into data/ (preprocessing, generator), nn/ (MLP, training, calibration), csp/, search/, integration/ with run_demo.py, and eval/ (experiments, dashboard) with tests/.

The 19 tests cover normal cases (all four CSP modes against the published solution, inference effect, AC-3 counters, generator uniqueness and seeding, search against a known answer and against brute force), edge cases (complete grid, empty grid, many-solution puzzle, no correction needed, correction limit) and impossible cases (duplicate givens in every mode, empty domain without duplicates, “unreadable”).

10Limitations and discussion

Why recovery is below 100%

In a diagnostic run of 60 puzzles with 2 injected misreads, every failure (17 of 60, 28%) had the same cause: the search found a cheaper set of corrections that also made the puzzle solvable, so the CSP accepted a valid but different puzzle. None of the failures was caused by the true cell being outside the candidate set. Using the optional “unique solution” goal raised exact recovery from 72% to 88% in that run, because most such alternative puzzles have many solutions.

Threats to validity

  • Injected, not natural, misreads. Misreads come from a documented rule over real hard digits. Real handwritten Sudoku would add other errors (segmentation, blank-cell detection, touching digits) that this project does not model.
  • Broken-first-reading filter. For k ≥ 1 we keep only instances whose first reading is unsolvable. Misreads that silently yield another solvable puzzle are, by construction, outside the study.
  • Cells of a clean MNIST type. Digits are centred 28×28 crops with different writers in train and test, but they are far cleaner than digits written in grid cells.
  • Search caps. A cap of 4,000 expanded nodes and a correction limit of 4 bound the 4-misread level; capped runs count as failures, which slightly understates recovery there.
  • Statistics. 5 seeds with 20 puzzles each gives 100 puzzles per level; the standard deviations across seeds (about 0.05 to 0.15) are large enough that small differences between Greedy and UCS recovery should not be over-read.
  • Experiment 2 conditions. Static variable order and a fixed cap are chosen to isolate the effect of the inference. Other variable-ordering heuristics (such as MRV, which the integrated system uses) were not part of this comparison.

What we would do next

  • Make “exactly one solution” the default goal and measure it with the same 100-puzzle protocol.
  • Re-estimate the candidate size (15 cells, 2 alternatives) and the correction limit against recovery and cost.
  • Replace the injection rule by photographed or hand-drawn Sudoku, with a cell-segmentation step in front of the network.
  • Train a small CNN and compare calibration with the MLP; add data augmentation for the hard classes.
The system is decision support for a reader of puzzles; it is not evidence that handwriting recognition is solved. Its value is that probability, search and constraints compensate for each other's weaknesses.

11Conclusions

  • A small NumPy MLP reaches {{acc_mlp}}% digit accuracy and, after temperature scaling, probabilities calibrated well enough (ECE {{ece_after}}) to be used as costs.
  • Searching over correction sets with the network's own probabilities turns a broken reading into a solved puzzle: exact recovery {{x1_nn}}, {{x2_nn}} and {{x3_nn}} for 1, 2 and 3 misreads, against {{x1_none}} without correction and at most {{x1_rand}} with random correction.
  • A* gives the quality of UCS with a fraction of the nodes, and the admissible conflict heuristic is simple enough to prove and to test against brute force.
  • Forward checking and AC-3 reduce CSP effort substantially on sparse puzzles, and AC-3 doubles as the detector that tells the integrated system the reading is broken.
  • The main weakness is the goal “solvable”: the cheapest solvable puzzle is not always the written one.
